# 补证清单 · 交由 00 协调

05 本轮不启动 Godot GUI，不自动操纵玩家会话、不制作新 PNG。以下是后续捕获需求，不是已执行记录。GUI 按当前任务留给实际用户/08；是否另行安排捕获由 00 决定。

## 最小补证

| 机制 | 缺失画面/动作 | 要回答的问题 |
| --- | --- | --- |
| Gate | 同一 source_face 的条件不足、满足条件、范围外请求、切换提交后；保留拒绝 HUD | 玩家是否能定位授权格，并把条件拒绝与范围错误区分开？ |
| Face Lock | 同一 Surface 锁的未触碰、未锁存错面、新匹配后仍留在锁上、锁存重入、Reset | 目标数字是否保持？状态和原因是否可见？不能用切换到 Inner 后锁不可见代替目标丢失证据 |
| Loop | 同一格两种真实 orientation；分别固定相机和切换 Q0–Q3 | 玩家能否区分姿态变化与观察方向变化？暗面数字是否还能辨认？ |
| Fork | 保持同一出发格/角色姿态，Q0–Q3 各一帧；Q1/Q2 实际动作/落地和 Q0/Q3 拒绝 | 两候选身份与高度是否可见？每次预测能否与正式结果对上？标签会否遮挡角色/边缘？ |
| 综合 | Surface 锁存→Gate→Inner 同姿态四视角→两个分流支路；保留真实事件元数据 | 单项线索在组合地图缩放与遮挡下能否继续使用？ |

优先 960×720 定位最小尺寸问题，随后补 1280×720、1920×1080；三尺寸应固定状态及相机，不能把不同视角的初始截图当严格缩放对照。不是要求自动生成全部组合或占用真人首玩窗口。

每帧至少记录 Build/source SHA、地图/世界、camera_quadrant、相机 size/keep_aspect、viewport 尺寸、当前位置和 orientation、mechanism state、required_local_face、尝试动作和正式 reason/result；相关事件有 session/run/generation/event 标识则一并记录。缺少读数应写 unavailable，不让美术推算 CONTACT 或合法落点。

## 真人理解记录要求（NOT_RUN）

使用实际新玩家、相同 immutable Build 和独立 QA profile；由 08 保留原始观察。05 不以已知路线测试、Solver 自动输入或专家看图代替首玩。可安排玩家不等于已有结果。

| 机制 | 观察者记录 | 判读边界 |
| --- | --- | --- |
| Gate | 首次指出可切换位置的时间、对拒绝原因的复述、范围外尝试次数 | 无法发现标签与不理解许可分别记录 |
| Face Lock | 操作前目标面陈述、错误接触后的解释、成功后能否说出目标面、是否借助提示 | 目标辨认和规划翻滚路径分开；不要求背熟代码枚举 |
| Loop | 到同一格前后的姿态描述、是否主动利用回环调整、换题是否复用方法 | 走对路线不等于解释了原理 |
| Fork | 每次动作前落点预测与理由、是否主动换视角、正式落点与预测原始计数、失败后的解释 | 不提前告诉 Q1/A 或 Q2/B；本报告的答案表仅供观察者 |
| 综合 | 首次观察/预测/计划时刻、无目的探索区段、卡点、提示时点、完成及迁移解释 | 时间/步数不是唯一指标；工具输入失败单独记，不算 Gameplay 卡关 |

保留原始次数、问题原话与提示记录；先报告样本事实，不凭小样本宣布全体玩家理解。真人测试尚未开始，以上各项没有正确率、发现时间或成功率可填。
