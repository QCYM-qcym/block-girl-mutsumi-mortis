## Short human session for 08 after Build acceptance

Recruit participants who have not seen witnesses or diagnostic traces. Record actual sample size and build identity. Use ordinary four-view controls only; never show solver routes or debug overlays. Begin with controls and the displayed objective. Use independent discovery where possible; mark every hint-assisted attempt.

| Map | Observe without supplying the solution |
|---|---|
| Gate | Can the player identify a conversion point and explain an off-point rejection? |
| Loop | Can the player predict/notice a different local face at the same corner, complete a return loop, then find the separate exit? |
| FaceLock | Does the player distinguish wrong contact from blocked movement, see the latch, and find the newly available gate? |
| Fork | Do view changes predictably change the landing, and can the player recover from the exploratory branch? |
| Combined | Can the player explain the sequence from pose planning to contact, Shift, view selection, landing and Goal? |

Record first prediction, attempted control/view, observed feedback, time to first understanding, prompts, Reset use and verbatim comments. For confusion, ask neutral questions: “你预期会发生什么？” / “这次和上次有什么不同？” / “你认为这是稳定规则还是异常？依据是什么？” Avoid naming the correct view or route. A hint after a recorded stall is allowed, but later success is assisted.

Stop mechanism-understanding scoring on a build with unreliable input, missing motion, wrong layer/landing or stale Reset animation. Record the technical defect separately. Reset discovery is a usability observation, not proof against softlocks. Owner09's eventual complete-graph result supplies that logical evidence.
