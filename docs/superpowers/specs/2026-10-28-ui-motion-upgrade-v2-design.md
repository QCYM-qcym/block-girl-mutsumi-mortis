## 2. 视觉方向：三层景观与编辑式信息

采用背景景观、中层信息版面、前层操作与状态三种深度，形成完整画面，避免继续堆空框。
背景使用已批准素材，保留主体与暗部层次；右侧景观保持充分对比，不盖大面积洗白渐变。
中层以章节标题、细分隔、进度、短说明与有功能的图标组织信息，密度来自内容关系。
前层集中主操作、当前选择、焦点与短反馈；每屏仍只有一个最强主操作。
品牌标题使用现有 NotoSerifSC，正文与数字使用 NotoSansSC，强化中文字重、字距和字号对比。
基色延续石白、墨色与青绿金属感；少量铜色用于章号、节点和角标，不做大面积亮金。
细象牙色边线、局部内高光、轻纸面细节共同塑形；避免多层巨大空框、强辉光和持续漂浮。
核心信息正文不低于 16px，主要操作和关键提示不低于 22px；次级辅助说明最低 14px，装饰性英文/序号不能承担唯一信息。
沿用 8px 间距基础；相关内容聚合，组间留白明显，图标、标题、数值及箭头按共同基线对齐。
hover、focus、pressed、selected、disabled 有完整状态；焦点使用可见轮廓和文字/图形共同表达。

## 3. 主菜单：品牌、继续卡与次级目录

左侧以品牌字标、短副题和章节索引建立识别，右侧景观提供有内容的纵深。
继续卡展示当前关卡正式标题、章节展示组、已完成数量及进度节点；有效存档存在时为主操作。
无有效进度时显示开始卡，不伪造继续位置；样例预览必须明确说明其进度是演示数据。
卡内设置层级清楚的主标题、简短状态说明、进度轨和开始/继续箭头，避免一块空白按钮。
次级入口统一包含图标、序号、标题、短说明和箭头，覆盖选关、设置及退出。
底部可放版本、操作提示与细章号，但不能出现未实现功能或新叙事设定的承诺。
新游戏确认沿用现有语义，明确真实影响；初始焦点落在安全返回项。

## 4. 选关：十个真实入口与两个展示组

来源为 `game/shell/level_catalog.gd` 合并的两个 `level_order.json`，标题以资源 `display_title` 为准。
第一展示组按现有顺序：`mutsumi_l01`、`mutsumi_l02`、`mutsumi_l03`、`mutsumi_l04`、`mutsumi_l05`。
第二展示组按现有顺序：`spatial_world_shift_gate_lab`、`spatial_orientation_loop_lab`、`spatial_face_lock_lab`、`spatial_perspective_fork_lab`、`spatial_rubik_spatial_puzzle_01`。
**主菜单与选关源注释必须写明：两组章名仅为暂定展示分组，不重命名正式关卡或正式 ID。**
分组标题与章节文案交给内容 Owner 核对；不新建解锁链、完成条件或跨章存档字段。
列表以节点串联进度，每项包含序号、正式标题、可达状态与明确的当前选择标记。
侧栏展示焦点项的真实可用预览、状态和短说明；无批准素材时写“暂无关卡预览”，使用中性占位。
未解锁项遵守现有不泄露地图原则；GREYBOX 不包装成已批准正式美术。
宽屏采用列表与侧栏；960×720 采用上下布局和列表滚动，返回及主操作持续可达。

## 5. HUD 与暂停：有组织的仪表组合

顶部组合章节/关卡身份、世界状态与视角方向；各项有图标、清楚文字和一致的刻度细节。
目标区显示正式目标与进度信息，底部集中按键提示与情境说明，形成统一仪表语言。
布局保留棋盘中央、角色周边和关键落点观察区；装饰不能侵入这些空间。
提示仅来自正式 `get_hint_presentation()` 与既有状态；不推断答案、权限或新增谜题提示能力。
提示、目标及短事件反馈按优先级避让；相同事件不重复生成常驻文字。
纯展示层鼠标透传；关闭操作提示后仍保留完成任务所需的状态辨识。
暂停页保留游戏背景，展示关卡与进度摘要，完整提供继续、重玩、设置、返回入口。
暂停入口即时响应；恢复接续既有动作生命周期，不复制 Tween 或重发已接受动作。

## 6. 设置：完整分组与事务状态

音频、画面、辅助各有图标与组说明；仅重新组织已有设置，不添加无实现的承诺。
音频含总音量、音乐、音效和静音；画面含全屏；辅助含减少动态、提示强度、对比度和操作提示。
每行由名称、简短说明、较短滑块/开关和定宽数值字段组成，数值右对齐且不拆行。
总音量占整行，音乐与音效并列成组，静音独立一行；音频层级在保留字号的前提下完整呈现，辅助页内容区可滚动。
提示强度沿用“最少 / 情境 / 加强”；不同控件的标签、命中区域与焦点顺序保持一致。
标题及底部应用/取消固定，内容区独立滚动；dirty 状态可辨，保存中防重复提交。
预览→应用保存/取消回滚、Esc 取消、配置版本保护与保存失败重试保持现有语义。
保存失败保留编辑内容、显示可换行错误并聚焦应用；错误不得覆盖底部操作。
从游玩打开设置先暂停，关闭后仍停在暂停页，由显式继续恢复游戏。

## 7. 动效方案

| 对象 | 常规拟议节奏 | 减少动态 |
| --- | --- | --- |
| 首屏景观、标题、继续卡、目录 | 分层入场；相邻错开 40–60ms，总计 500–650ms | 非必要位移全部关闭，仅 alpha ≤80ms |
| hover / focus | 120ms，色彩、边线与轻表面变化 | 即时或 alpha ≤80ms |
| press / release | 80ms / 110ms | 即时或 alpha ≤80ms |
| 暂停、设置等模态 | 180–220ms，遮罩与面板统一节奏 | 仅 alpha ≤80ms |
| HUD 短反馈 / 通关强调 | 复用 V1 单次反馈原则，文字保持稳定 | 静态状态或 alpha ≤80ms |

首屏展示动画不锁住按钮；点击、键盘与关闭均立即响应，不能等待完整入场结束。
换页、销毁、重置、离关时取消旧动效；快速切换不积累回调或面板。
UI 减动规则不重写角色正式 sampler 时长；角色动作中改偏好仅影响后续接受动作。
World Shift 保留 Host 在 Presenter 清空后的互斥角色写入窗口，禁止并发 transform writer。
相机、World Shift、角色与 UI 的减动偏好由 Integration 接到现有 Owner，保留输入清理与最终姿态。
