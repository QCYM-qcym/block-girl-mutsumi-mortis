日期：2026-10-28。状态：**待用户审核的设计规格；尚未批准产品实现**。

本设计满足用户“全面升级 UI + 动效、不要重复造轮子、可找开源”的目标。

## 1. 目标、方案与批准边界

升级应让信息更清楚、操作更可靠、反馈更连贯，并延续正式游戏已有的安静气质。
精致来自文字层级、间距、对齐、状态细节和受控节奏；不依靠增加纹理、面板和装饰数量。

| 方案 | 收益 | 代价及判断 |
| --- | --- | --- |
| A：延续现有视觉并统一精修 | 保留美术连续性，复用字体/图标/Theme，集中改善流程与动效 | **推荐**；需消除 Shell 与 Game Feel UI 的视觉及状态割裂 |
| B：另建新视觉语言 | 可彻底重塑品牌呈现 | 资产、兼容与 QA 成本高；当前不优先，需另行批准范围 |

本稿只提供可审核设计、工程边界和验收要求；后续实施应另建批准后的任务与 allowlist。
A2 仍未批准；本稿不批准 A2，也不把设计图视为美术批准。
正式 frozenArt 保持冻结；Runtime、地图、关卡 ID、解锁规则和 Save 语义保持不变。
不修改谜题、正式动作权限、轨迹合同、输入映射、存档格式或场景管理架构。
不因引入开源参考而增设第二套 Save、Audio、SceneManager 或 Runtime。

## 3. 视觉系统

- 以现有 `face #e0e3db`、`ink #162333`、`accent #5c919b` 为起点，背景与正文保持明确明度层级。
- 使用浅石色容器、深墨正文、少量青绿重点；章节与世界状态不能只靠颜色区分。
- 中文标题复用 NotoSerifSC，正文/数字/操作说明复用 NotoSansSC；不新增字体家族。
- 以 8px 间距为基础，24px 为最低常用外安全距；局部图标与基线允许 4px 对齐修正。
- 容器克制使用细线、轻圆角和层次；避免多重描边、大面积光晕和持续漂浮装饰。
- 主要动作、次要动作、危险确认和禁用状态必须有一致样式；每屏只设一个最突出的 primary。
- 普通正文最低 16px，主要行/关键提示最低 22px；小窗口通过重排与滚动保住可读性。
- 高对比度模式覆盖正文、焦点、状态与提示；不能只覆盖某一个 CanvasLayer 的 Label。
- 沿用 `production/ui/beta_shell_01/fonts/` 与 `icons/`，保留既有 OFL/图标来源及许可记录。

## 4. 页面与信息架构

### 主菜单与新游戏确认

主菜单使用大幅留白、明确标题和一个 primary：存在有效进度时为“继续游戏”，否则为“开始游戏”。
选关、设置与退出形成次级列表；版本信息与帮助降为低优先级，不与主操作争夺注意力。
新游戏确认清楚说明影响，默认焦点落在安全返回动作；保持现有清档/开始语义。
背景复用批准的正式素材，文字区域优先保持稳定对比度，不添加新叙事插图。

### 十关选择

十个正式入口按现有两章概念分组展示；分组仅改变展示，不改 ID、顺序、解锁和完成判断。
章节标题与关卡序号承担导航；每行显示标题、已通关/可游玩/未解锁状态及统一图标。
焦点或悬停可更新预览；未解锁关卡保持既有不泄露地图原则，缺正式预览时显示诚实占位说明。
1920/1280 宽屏可保留侧向预览；960×720 采用上下结构，关卡列表滚动，返回/设置始终可达。
章节展示文本由 06 核对现有内容，07 不自行重命名关卡或创造新的章节进度规则。

### 游戏 HUD 与暂停

HUD 收敛为章节/关卡身份、世界与视角、当前目标、按需出现的情境提示。
输入说明作为可关闭的低优先级底部提示；反馈只在相关事件出现，不常驻重复教学文字。
HUD 从正式 `get_hint_presentation()` / 现有状态获取内容；不自行推断答案、落点或权限。
顶部反馈、目标区与底部提示建立互斥/避让规则，保住地图观察区与角色周边空间。
纯展示层保持鼠标透传；暂停层清楚保留当前游戏背景，主要操作为继续，次要为重玩/设置/返回。
暂停后角色动作与相关表现按既有生命周期冻结；恢复后接续，不启动第二份补间。

### 设置

设置作为清晰模态，按“音频 / 画面 / 辅助”分组；只重新组织已有选项。
音频含总音量、音乐、音效、静音；画面含全屏；辅助含减少动态、提示强度、对比度、操作提示。
滑块同时显示明确数值；提示强度显示“最少 / 情境 / 加强”，不暗示新增谜题帮助能力。
内容区可滚动；标题、保存错误与底部应用/取消保留稳定位置，错误换行不得遮住主操作。
保留预览 → 应用保存 / 取消回滚事务；Esc 等价取消。保存中阻止重复提交。
保存失败留在模态、恢复编辑、说明错误并聚焦应用；无效/更新版本配置保持原配置。
从游玩打开时先暂停；关闭后保持暂停，恢复游戏由显式继续操作完成。

### 通关

通关采用一次短仪式：状态确认 → 标题/简短完成说明 → 下一关或返回 / 再玩一次。
最终关不显示不存在的下一关；保存失败或未保存状态沿用真实结果，不以庆祝遮盖。
庆祝只能响应既有通关权威；单次运行只触发一次面板/强调/Goal 音效。

## 5. 动效语言与参数建议

下表是实施起点；调整需随真实 Godot 录屏审核，不能改变 Runtime 的接受、提交与完成时序。

| 场景 | 常规建议 | 减少动态 |
| --- | --- | --- |
| hover / 键盘焦点 | 120ms，颜色/细线变化；保持稳定可见焦点 | 即时或 alpha ≤80ms |
| 按下 / 释放 | 80ms / 110ms，轻微表面反馈 | 颜色即时或 alpha ≤80ms |
| 页面退出 / 进入 | 180ms / 240ms，统一方向的轻位移+淡变 | 仅 alpha ≤80ms |
| 模态出现/关闭 | 180ms，遮罩与内容协调进入 | 仅 alpha ≤80ms |
| 情境提示 | 160ms，淡入淡出，文本不逐字跳动 | 仅 alpha ≤80ms |
| Goal 短强调 | 320ms 单次强调，之后静止 | 静态完成状态或 alpha ≤80ms |

所有交互立即响应；动画期间的重复输入采用现有动作防重规则，不能累积页面或重玩请求。
新动效使用共享参数与取消路径；控件销毁、换页、重置或离关时终止旧 Tween。
减少动态关闭位移、弹性、晃动与循环呼吸；功能性焦点和完成反馈仍完整可见。
UI 的短淡变规则不替代角色正式动作 sampler，也不强制将正式动作压缩为 80ms。
角色 roll/fall/landing/edge 优先调优现有参数、节奏与纯表现采样，不新增 transform writer。
World Shift 保留 Host 在 Presenter 清空后的既有互斥写入窗口；不能把该窗口误改为两者并发控制角色。
`cube_presenter.set_reduced_motion()` 只影响后续接受动作；进行中的配置/轨迹/版本保持冻结。
WorldShift 与 Camera 的减动覆盖缺口必须由 00 统一接线，明确同一偏好如何传到现有 Owner。
任何相机/世界动效均须保留准确世界、视角、输入清理与最终姿态；视觉效果不能授予动作权限。

## 6. 复用与第三方接入

原生 Godot Theme、Control、Container、ScrollContainer 与 Tween 是默认底座。
复用现有 Tokens、Stone 控件、设置事务、AudioDirector 和角色表现；只抽取确有重复的视觉/动效参数。
候选参考：[Maaack/Godot-Menus-Template v1.7.1](https://github.com/Maaack/Godot-Menus-Template/tree/v1.7.1)，MIT。
仅选择性参考菜单焦点与导航组织，不能整套导入其 Save/Audio/SceneManager 接管现有实现。
若原生 Tween 与已有配方不足，可评估 Tweens2D；优先借鉴配方，版本与许可核实后才决定接入。
当前没有 vendor、安装或执行这些候选，也没有 Godot 4.7.2 实测兼容性结论。
实施接入时必须固定来源 URL、版本/tag、完整 commit/hash、许可证及实际拷贝文件清单。
复制代码应保留版权头与许可，登记修改；未实际使用的候选只列参考，不计入已接入依赖。
新增依赖须证明解决具体缺口，并在真实入口通过三尺寸、焦点、生命周期验证后才接收。

## 8. 验收条件与证据门槛

以下 12 条全部适用于真实入口，必须记录结果；静态预览与 doubles 不能替代实机/正式链路。

1. 完整流程：主菜单、十关两章、游戏、暂停、设置、确认、通关、重玩和返回都能走通。
2. 键鼠等价：Tab/Shift+Tab、上下、Enter/Esc 与点击/拖动均可完成流程；滑块左右调整不误触导航。
3. 状态清晰：hover、键盘焦点、按下、禁用、当前选择均可辨认；焦点不依赖动画或颜色单一线索。
4. 模态可靠：游戏输入被拦截，关闭后恢复合适焦点；隐藏控件无残留焦点，暂停/继续无穿透输入。
5. 三尺寸强测：1920×1080、1280×720、960×720 均无重叠、截断、越界、横向滚动和不可达主操作。
6. 滚动可靠：最长中文、十关、全部设置、错误长文均可读；焦点自动滚入，应用/取消与返回可达。
7. HUD 正确：内容只读正式状态，目标/世界/视角/提示正确，反馈不重复遮挡，装饰鼠标透传。
8. 设置事务：预览、取消回滚、应用、失败重试、无效版本保护、跨重启持久化均与原语义一致。
9. 减少动态完整：菜单、HUD、模态、角色、世界与相机逐项有对照证据；操作信息不因减动丢失。
10. 动作配置冻结：动作中改偏好只影响后续接受动作；当前轨迹、COMMITTED 与完成回调保持正确。
11. 权威与单写者：沿用 Presenter 与 World Shift Host 的既有互斥角色写入边界，UI 不推进 Runtime；暂停、恢复、取消、卸载均无遗留写入。
12. 重玩完成闭环：动作→完成→重玩→再次完成在两种模式通过；旧 session/run/generation 回调不污染新局，通关/解锁/保存/音效不重复。

生命周期重点覆盖 roll、Fall/Landing、Edge、WorldShift/Camera 的启动、途中暂停、恢复、重置和离关。
GraphicalReplay 至少覆盖真实动作完成与中断/重置，复核最终姿态、事件顺序和旧身份过滤。
可复用测试入口包括 `tests/beta_sprint/game_feel_owner_01/test_graphical_replay_real.gd`、`test_graphical_replay_lifecycle.gd`。
设置回归参考 `tests/beta_sprint/spatial_formal/shell_settings.gd`、`tests/beta_sprint/game_feel_owner_03/test_settings_process.gd`。
既有 Save 与流程验证位于 `tests/shell/`；由 03 选择实际适用检查，补充行为缺口而非复制实现测试。
通过门槛：所有适用自动检查 PASS；三尺寸/两种动态模式流程 PASS；阻断/严重缺陷清零；指定 Build Human QA PASS。

构建、录屏和截图存入新的唯一批次，记录基线/交付 SHA、Godot 版本、Build/hash 与检查范围。
新 Build 不覆盖旧 QA 包、旧截图或冻结清单；旧 QA 只能作历史对照，不能继承到新 Build。
